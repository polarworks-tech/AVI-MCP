# カテゴリE: シーン・プロジェクト構造操作 設計書

対応する要件: [REQUIREMENTS.md#カテゴリe-シーンプロジェクト構造操作](../REQUIREMENTS.md)

[DESIGN_POLICY.md](../DESIGN_POLICY.md)の方針により「原則やらない/最小限」とする
カテゴリ。設計書としては骨格のみ定義し、明確な需要が出るまで実装しない。

## 対象API

| API | リスク要因 |
|---|---|
| `create_scene` / `select_scene` | シーン関連操作はAviUtl2本体がUndoに非対応(aviutl2.txt記載) |
| `set_scene_size` / `set_scene_frame_rate` / `set_scene_sample_rate` | 同上、既存シーンの設定を破壊的に変更する |

## 実装する場合の最低要件(着手時に再検討)

- ツールの説明文に「この操作はUndoできません」と明記する
- 実行前の確認(現在のシーン一覧・設定値を返す読み取りツール)を先に提供し、
  エージェントが「今どういう状態か」を踏まえてから呼び出せるようにする
- 既定で無効化し、明示的なオプトインを要求する([DESIGN_POLICY.md](../DESIGN_POLICY.md)の
  カテゴリF向けの考え方をそのまま適用する)

## 現状の結論

カテゴリA/Bが安定し、かつ実際に「シーンを増やしたい」という要求が出てから着手する。
それまでは本書を骨格のまま保持する。
